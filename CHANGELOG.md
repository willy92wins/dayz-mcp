### Added

- A3 (fb-20261028-131246-964e): `acquire_registry_lock_with_retry` in `tools/dayz_mcp/registry_lock.py` retries only `launcher_registry_busy` with bounded exponential backoff (0.05 s → 0.5 s by default) until a 5 s deadline, then raises `launcher_registry_busy_timeout`; `acquire_registry_lock` stays fail-fast and every other error propagates without a retry. The registry callers now acquire through the retry wrapper, keeping their shared/exclusive mode: `open_approved_launcher` in `tools/dayz_mcp/launcher_registry.py` and the install, replace, rollback and `describe_registry_provenance` paths in `tools/dayz_mcp/launcher_registry_update.py`, so transient contention no longer fails them and exhausted contention raises `launcher_registry_busy_timeout` instead of the first-attempt `launcher_registry_busy`. New guide `docs/SERVERMOD.md` explains loading the addon only on the server with `-serverMod=` (server-only `MissionServer`/`MCPBridge` vs client `MCPClientBridge` in `MissionGameplay`; a correct client start emits `[MCP-CLIENT] client config loaded path=…`, `[MCP-CLIENT] client init pending: …` only on init failure, and no `[MCP-CLIENT]` line at all in the client RPT is a hint — not sole proof — of a server-only load); it is not yet confirmed against a real run — that check stays queued with Experto MCP. The three async consumers in `tools/dayz_mcp/dayz_test_tool.py` (preflight, `dayz_test_run`, `dayz_test_stop`) now open the launcher via `asyncio.to_thread`, so the synchronous retry sleep no longer stalls the event loop, timers or cancellations; a launcher acquired by the worker after cancellation is closed so its lock is not leaked. No `addon/`, `config.cpp` or launch-argument change.

### Fixed

- Unconfigured `TryInit` no longer runs on every frame (A2, fb-20261028-131212-b320). `MCPBridge` and `MCPClientBridge` attempt init on the first tick, then once every `INIT_RETRY_S` (1.0 s): each tick adds its timeslice to `m_InitAccumS` and the attempt sets that accumulator back to 0. There is no `CallLater`. `ia` / `init_attempts` counts those attempts, not frames. `LogInitFailure` still logs one line per session and is not cleared on a retry. On the client, `MCPPlayerTrace.Tick`, `TickCameraHandoff` and `m_JobRunner.Tick` still run every frame; only the `TryInit` call is spaced, and a tick that is still unconfigured still returns before the poll. Needs a PBO built from this release. Not exercised in game by this change.
- FIFO/reservations remain available with v12 peers: lease-end stage 2b stays inert until PBO v13 announces `lease_close` / `lease_close_client`. The broker checks the bound peer's capability census (no environment flag); unsupported closes settle without queued commands or OWED rows, so later grants do not inherit `lease_end_unconfirmed`. Bridge protocol version 12 and the server argument-contract hash are unchanged; this F1 broker fix alone needs no PBO rebuild (PR #268 as a whole touches `addon/` and does require one).

### Fixed

- An optional argument the caller omits no longer reaches Enforce as 0: an `object_anim` read no longer writes phase 0 (which had looked like car doors not holding a phase), and a partial `world_weather_set` no longer zeroes the other levels; `world_time_set` and `infected_drive` are covered too. The wire carries `<field>_set: true` beside each optional value, and the daemon refuses a value without its flag (#162).
- The daemon works from a Python 3.11 or 3.12 venv: its identity checks, the orphan reclaim and the legacy port reclaim accept the venv redirector's rewritten `argv[0]`, and the request parser fails closed as `json_undecodable` on nesting too deep for the 3.11/3.12 decoder (#112, #116, #126, #130).
- DayZ Tools on another drive: the bundle verifier finds DayZ Tools the way the builder does (`DAYZ_TOOLS_PATH`, then the registry, then the default), and the sealed launcher starts AddonBuilder from the sealed layout instead of a fixed `C:` path (#123, #128). On a fresh clone the launcher registry lock is created, the builder takes the Windows SDK paths from `tools/dependency-lock.json` instead of a fixed `C:` path, a bundle can be published onto another volume, and README's "Before the first test run" lists the host setup a first run needs (#114).
- `dayz_test_run(build=true)` through the native launcher no longer stops at `native_debug_gate_rejected:unapproved_debug_image`: in the AddonBuilder tree only, the debug gate admits a closed list of Valve-signed Steam client DLLs from the pinned Steam directory and Valve's `bin\x64launcher.exe` (#141, #152, #158).
- Fail-closed path checks (the daemon keyfile, host-config provenance, the installer's CLI path) accept an 8.3 short path to the same file instead of refusing it (#138).
- A session keeps its lease across `server_reload`: the handoff carrier follows heartbeats and lease-renewing commands (`lease_id` in `/enqueue` and lifecycle replies), a release or an invalidation clears it, and its I/O runs off the event loop. A reload that inherits an expired lease recovers without disturbing live or queued leases (#92, #119, #131).
- `session_release` of a token this client still held after a silent TTL answers `lease_expired` with `next_step=session_acquire_wait` instead of `lease_invalid`, and a heartbeat with an expired lease says it expired, even while a fence is up, instead of "token was never valid" (#77, #136).
- Remaining times (`expires_in_s`, queued tickets, grace `remaining_s`) never exceed their caps. `wait_for` never starts a probe after its deadline, and its wait for `tool_lock` counts against `timeout_s` (`timed_out` with `last_error=tool_lock_busy`) (#118, #127).
- In client mode, the readiness probe before a world read is capped by the caller's remaining deadline, so a slow probe no longer stretches the call (`da22937`).
- `dayz_test_stop` succeeds when DayZ is already gone instead of reporting `run_stop_failed` with `cleanup_degraded=true`; a run still alive after a failed stop still fails (#86).
- A lease grant adopts an ownerless `RUNNING_IDLE` or `UNRECONCILED` run whose owner is an empty string; it used to leave `adopted_run` null, and `dayz_test_stop` answered `run_not_adoptable` (#87).
- Manifest backups under `lifecycle-recovery-faults/backups/` stay bounded: the newest 200 plus every one a pointer or a fault names, with at most 128 removals per checkpoint (one host held 1.1 GB of them). A replace blocked by another reader retries for up to 1 s, and a backup a crash left incomplete is quarantined instead of stopping the daemon with `invalid_lifecycle_manifest_backup`. The doctor warns `MANIFEST_BACKUP_RETENTION_STALLED` and `MANIFEST_BACKUP_QUARANTINED` (#53, #63).
- When the MCP host is an MSIX app (Claude Desktop, Codex), the daemon is spawned through WMI, outside the app's registry virtualization, and the stdio Steam check reads the real `HKCU`, so a live, logged-in Steam no longer gets launches refused. `DAYZ_MCP_DAEMON_SPAWN_WMI=0` turns the WMI spawn off (#91).
- Starting a run no longer activates DayZ windows on launch, and the capture helper no longer opens a console window (#59). DayZ still takes the foreground for about 2.5 s once started, whatever the window's initial state; that is the game's own activation (measured 2026-09-30; see Known issues).
- Releasing a scripted `lookat` camera with `restore_gameplay` no longer freezes the client render: the view goes back through a FreeDebugCamera handoff, as vanilla's camera tools do, and the reply is posted when the handoff ends. `render_frozen_signal` also fires for a near-still frame pair (#167).
- `vehicle_control` applies brake and handbrake whatever the engine state and starts the engine only when `throttle` is above 0; a release restores the car's brakes-without-driver, as vanilla does (#170).
- `pipeline_inbox` no longer loses an entry, or the whole read, when a record holds U+2028, U+2029, U+0085 or an undecodable byte: records are split on the newline each one ends with and decoded one by one (#169).
- Concurrent inbox writers no longer lose or tear records: every append holds a cross-process lock on `feedback.jsonl.lock` (bounded at 10 s, then `inbox_busy` and nothing written), and a new id is checked unique under it (`inbox_id_collision` after 16 draws). Measured with the old code on Windows, six concurrent writers kept 255 of 300 records of about 1 KB. The id format, the size limits and the record fields do not change (#179).
- A daemon started from an interpreter other than `tools\.venv-mcp` prints one line naming both interpreters and exits 78 instead of a traceback and exit 1 (#184).
- A stop that races the reaper succeeds honestly (`stop_method: already_exited`) instead of `run_stop_failed` with the box free, and a DayZ launched by `start_run` survives a daemon crash between the launch and the manifest: a versioned `launch-intent.json` written before the launch lets the next daemon start record the orphan when exactly one process matches its argv hash, launch window and profile token (#185).
- `player_teleport` skips its occupant precheck when no client peer can answer it, instead of timing out on that probe (#76).
- `notify_players` with no connected player returns `{ok: false, sent: 0, error: "no_players"}` instead of `sent: 1` (#85).
- `object_inspect` echoes a malformed `type` in its `bad_args`, and a call with neither `type` nor `object_id` names both legal forms (#79, #84).
- `camera_set` restores gameplay when applying the camera fails after the controls were suppressed (#97).
- `capture_screenshot` reports a grab that never started as `capture_start_timeout`, apart from `capture_timeout` (#136).
- In DayZDiag, a client take to hands no longer throws a NULL pointer: the addon registers `PluginInventoryDebug`, which vanilla registers only when `IsDebug()` is true (#160).
- Fresh-launch `bridge_status.ready` no longer reports `server_poll_stale` from a dead pre-launch peer's leftover poll ages; the verdict is `binding_not_ready` until this generation's first accredited poll. The `ready` object comes first in the payload, publishes `stale_threshold_s` plus per-peer ages, and when `ready` is false names `next_step` (a public tool) before the ages (#77, #78).
- User-facing fence and lease errors name only public MCP tools (`session_status`, `bridge_status`, `session_acquire_wait`) and carry `next_step=`; they no longer cite internal `lifecycle_status` (#77).
- `dayz_knowledge_find` / `show` no longer route to `dayz_knowledge_prepare` when `can_prepare` is false; the error is `knowledge_pack_missing` / `knowledge_pack_invalid` with the install command, and `dayz_knowledge_status` publishes `install_command` (#77, #78).
- Untrusted clients keep the lease-free reads, `server_reload` and an owned `dayz_test_stop` when policy revalidation fails, including the stop of their own idle run; authority changes stay fail-closed (#30, #43).
- A bare `ClientRuntime` defaults to rejecting a stale policy (#37).
- Native job cleanup no longer fails with `native_job_cleanup_incomplete:active_zero_wait_timed_out` when the second wait already ran and no handle remains open (#40, #41).
- `python -m dayz_mcp.doctor` parses supervised registrations and `--exec-audit-path` again, so it checks the daemon instead of reporting `CONFIG_UNREADABLE`. The audit path is now compared as part of the daemon policy (#48).
- `pack-addon.ps1` passes `-packonly` when the source has no `.p3d`/`.paa`/`.rvmat`, matching the test worker so AddonBuilder does not binarize against every `config.cpp` under `P:\` (#57).
- `capture_screenshot` launches the grab without an inherited `PSModulePath`, so a Git Bash-poisoned module path cannot hide PowerShell cmdlets (#57).
- `vehicle_release` Abort autodumps a live trace before clearing it; stop the trace in a separate call, then release (#57).

### Security

- DayZ, and Steam when dayz-mcp starts it, run with a whitelisted environment instead of the agent's, so the agent session's environment variables (API keys and other secrets) no longer reach those processes or their crash dumps (#144).
- The daemon checks the arguments of every whitelisted bridge verb against an ingress schema: the 16 verbs that accepted any payload (`world_spawn`, `camera_set` and `vehicle_control` among them) now refuse extra, missing or mistyped keys with `bad_args`, and a verb without a schema is refused (#117).
- Strings from identities or persisted state that reach MCP payloads (the registration stamp, daemon generations, stop-envelope state and reason, retired-run diagnostics) are echoed only when they match a closed shape (#46, #47, #66).
- Both bridges accept only an exact loopback REST URL, `http://127.0.0.1:<1-65535>/`, instead of anything that starts with `http://127.0.0.1:` (#173).
- `dayz_test_close` is denied inside playbooks, next to `dayz_test_run` and `dayz_test_stop` (#175).

### Known issues

- DayZ still takes the foreground for about 2.5 s when the server starts and again when the client starts. That is the game's own activation: starting the server minimized did not avoid it (#168, reverted in #180; measured 2026-09-30). Tracked as fade and 75e7; f298, which #59 fixed on the Python side, is closed.
- A `storage_1` rotation (another mod set used the same mission since the last run) resets the mission's world and characters, but `dayz_test_run` does not say so; the notice is only in the daemon's audit (`lifecycle_storage_rotated`) (c8c7).
- Reported by other sessions, not yet reproduced here: when AddonBuilder binarizes a project (`build=true` with `.p3d`, `.paa` or `.rvmat` files), binarize reads every `config.cpp` under the folder AddonBuilder passes as `-addon`, which can be the parent of the source or a temp root, so a broken `config.cpp` elsewhere fails the build (bf5c, 8cf9). A source reached through a Dokan-mirrored `P:` drive makes binarize exit at once (a97e). Publishing a rebuilt launcher bundle fails with WinError 5 or 32 while a live MCP client still holds the previous one (7672).
