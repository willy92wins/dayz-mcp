## [1.3] - 2026-10-01

### Added

- 13 new public tools, 75 in all (62 in v1.2), plus `exec_enforce` when an allowlist is configured: `dayz_test_close`, `input_describe`, `object_doors`, `weapon_state`, `hands_take`, `weapon_raise`, `weapon_aim`, `weapon_fire`, `weapon_sights`, `anim_timeline`, `vehicle_door`, `input_trigger` and `world_time_get`. The bridge verbs among them need a PBO built from this release (#73, #133, #134, #149, #157, #161, #174, #182).
- `world_time_get` reads the in-game date and time without a lease, in its own `world_time {year, month, day, hour, minute}`, normalized like `world_time_set`'s echo (the raw read stays in `world_time_echo`); an incomplete answer fails closed with `world_time_incomplete`. The time multiplier cannot be read: DayZ 1.29 has no script getter for it (#182).
- `daemon_reaccreditation_failed_open_new_session` carries `reaccreditation_stage` (seven stages from its five raise sites) and a remedy that is true for that stage; only `replay_identity` needs a new daemon generation. The doctor's `diagnostic_failure` names `failed_check` and `exception_class`. An `internal_failure` from the sealed worker carries `reason=sealed_worker_exception`, and when the serving process's sources are stale, `dayz_test_run` and `dayz_test_stop` say to call `server_reload` or reopen the client (#184).
- `ui_click(mode="complete")` works: it measures the widget's screen box and sends `OnMouseButtonDown`, `OnMouseButtonUp` and `OnClick` at its centre, in that order, through the same handler walk as direct mode, so a panel that acts on mouse down or up can be driven. With `bubble=true` a handler that declines passes the phase on up the chain. The reply's `click_sequence` gives the centre and, per phase, the handler and whether it consumed; `ok` means some phase was consumed. It is a script-level synthesis of handler calls: no OS input, no cursor move, no focus and no hit test (#187).
- A packed PBO names the commit that built it: `tools/pack-addon.ps1` writes `mcp_build.json` (commit, addon tree id, build time and source) into the staged addon, and Enforce never reads it. `tools/make_release.py` refuses a PBO without exactly one valid marker (`pbo_marker_missing`, `pbo_marker_invalid`) or whose commit is not the `git_sha` in `VERSION.json`. `tools/dev/` holds the release process's own tools: `pbo_provenance.py` compares every PBO entry with `addon/` at a ref, `setup_worktree.sh` creates a worktree and its venv, and `swap_pbo.ps1` replaces the installed PBO while DayZ is stopped and keeps the previous one beside it (#181).
- `input_trigger` drives a mod's key handler without OS input or window focus. `kind=key` delivers one key to `GetGame().OnKeyPress/OnKeyRelease` (`entry=game`, which reaches a modded `DayZGame` and menus) or to `Mission.OnKeyPress/OnKeyRelease` (`entry=mission`, what `key_press` does), as a `click`, a `hold` (up to 10 s), or a `press` that stays held until `release`, its `ttl_s` (up to 30 s), `restore_gameplay`, a player change or shutdown; one key is held at a time (`input_trigger_busy`). `entry=game` never presses F4, LMENU or RMENU (`would_request_exit`), because DayZDiag's Alt+F4 check would exit the game. `kind=input` names why a `UAInput` cannot be driven: `input_not_drivable` with `reason=no_local_setter` (no script API sets it in DayZ 1.29), `input_unknown`, `input_locked` or `input_denied` (#174).
- Playbook `ask_restart` (DRAFT): one `ui_dialog` confirm before an agent restarts the game. Only the player's Yes is PASS; No, Cancel or Esc, a timeout, a disconnect or a dialog already open are FAIL `restart_not_confirmed`, with the real answer in `steps[0].observed`. It closes, stops and launches nothing (#175).
- What DayZ writes on stdout/stderr is kept in `<exe>_<time>_<pid>.stdout.txt` / `.stderr.txt` beside the role's RPT when the launch names an absolute `-profiles` folder: the first 4 MiB of each stream, then its last 64 KiB after a marker. A process that writes nothing leaves no file (#177).
- `dayz_test_run` names two start failures. `client_start_stalled`: the client's RPT has held only its header for 15 s and no poll arrived; under the start budget it is a refusal whose remediation names `client_start_budget_s=0`. `server_start_hung`: the server's RPT had been silent for more than 75 s when a readiness timeout stopped the start; it can only appear with `server_wait_s` above 75 and relabels the timeout, nothing more (#177).
- Every `audit_failed` from the session coordinator names the step that failed in `audit_stage` (`write`, `gate`, `wal_arm`, `wal_transition`, `wal_clear`, `snapshot`, `compensation`, `reservation`, `expiry`, `fault_latched`, `grant_latched` or `handoff_latched`), and the caller reads `audit_failed; audit_stage=<stage>; next_step=session_status` (#176).
- `dayz_test_close(run_id, graceful_timeout_s=45)` closes the windows of a `RUNNING` run the calling session owns and never terminates a process. On a client-and-server run it closes the client first and waits for each connected player's logout line (at most `min(30 s, graceful_timeout_s)`) before it closes the server. It reports `graceful`, `stop_method`, `close_order`, `logout_wait_s` and `logout_players`, and warns `player_state_not_saved` when a logout never appeared. `dayz_test_stop` keeps its kill path (#73, #136, #142).
- Native weapon control of the local player, with no OS input and no window focus. `weapon_state` (a read, no lease) reports the held weapon's muzzles, chamber, magazine, jam, fire mode and a server-side shot counter. `hands_take(object_id)` takes a spawned item within 2 m, or one from the player's inventory, to hands; the take is predictive, so confirm it with `weapon_state`. `weapon_raise` (held 3 s by default, 30 s at most), `weapon_aim`, `weapon_fire` and `weapon_sights` are lease-gated and time-bounded, and fire and raise are applied on the server, so a shot counts (#134, #149, #151, #159).
- `input_describe(name)` reads on the client whether an input is registered and, for its selected alternative, its keys and devices, lock and conflicts. `exists` is the engine index (`ID() >= 0`), and a raw `probe` shows why it is false for an unknown name (#133, #147, #153).
- `object_doors` reads the engine's state predicates of each door of a building (open, opening, ajar, closing, closed, locked, ...) and the door's `pos`; anything else answers `not_a_building` (#133, #156).
- `action_use` gains `target` (`world`, the default; `hands`, the item in hands; `self`, vanilla's no-candidate target for actions such as `ActionDrink`) and `door_index`, which targets one door of a building. Both go through new client commands (`action_use_target`, `action_use_door`), so an addon that does not announce them answers `target_not_supported` / `door_not_supported` and runs nothing (#70, #156, #158).
- `vehicle_door(source, mode, object_id | type+pos)` reads, opens or closes one car door the way the server half of vanilla's `ActionCarDoorsOutside` does. `mode` (`read`, `open`, `close`) is required, so a call without it never writes; confirm a write with a later `mode=read` (#161).
- `anim_timeline` records on the client, for the next action, the local player's action-callback state transitions and the held item's animation phases, with `start` / `status` / `stop` / `read` / `clear` like `vehicle_trace` (#157).
- `world_spawn(..., lifetime_s)` sets the spawned entity's economy lifetime (up to 3888000 s), so a vehicle fixture is not deleted by the CE cleanup once the player is more than 100 m away. The reply carries `lifetime {remaining_s, max_s}`; an object that is not an `EntityAI` is deleted and refused with `lifetime_unsupported` (#164).
- `dayz_test_run(mode="server", navmesh_data_server=true)` adds `-startNavmeshDataServer` to the server launch for DayZ Tools' NavMeshGenerator; outside a server launch it is refused with `navmesh_data_server_requires_server_launch` (#150).
- `dayz_test_run(on_busy="queue")` waits in the box FIFO (for `wait_for_box_s`, else up to 600 s) instead of failing at once. Busy results carry `queue_offer` (`null` when waiting cannot free the box), and `session_status.box` gains `queue_position` and `queue_offer` (#74).
- A lease that expires (120 s TTL) while a run is attached to it leaves its former holder 90 s to acquire again first (`LEASE_GRACE_S`) while other sessions queue. `dayz_test_run` refuses to launch over another session's `RUNNING` run with `takeover_required` unless `takeover=true`, which stops that registered run first and names `evicted_run_id` (`edc7bb3`, #31).
- `session_status.box.runs[]` rows say who is using each run: `use_state` (`agent`, `unknown`, `human`, `idle`, `idle_waiting` or `abandoned`), `use_reason`, `idle_s`, `human_input_age_s` and `launched_by`, from the host's last-input tick and foreground window; no window titles or input content are read (#125).
- An idle warden in the daemon, off by default: only `{"enabled": true}` in `%LOCALAPPDATA%\DayZ_MCP\idle-warden.json` turns it on. It then warns the player of an `abandoned` run with `notify_players` and closes the run 60 s later unless someone reacts (#139, #145).
- `--no-progressive-disclosure` makes client mode list every tool, with its full description, before a lease; lease-gated tools still refuse to run without one. The installers add it to the Claude registration only (`-ClaudeNoProgressiveDisclosure` / `--claude-no-progressive-disclosure`) (#113).
- `--tool-pack local8b` (or `DAYZ_MCP_TOOL_PACK=local8b`) gives a stdio client a smaller catalog for small local models; the default stays `full` (#79).
- Successful mutating bridge results carry `next_step=session_heartbeat`, session tools name their public follow-up (`bridge_status` after an acquire, `session_acquire_wait` after a release), and OK bridge results carry at most two `suggested_calls` that exist in the caller's catalog (#79, #81).
- `session_status` carries `runs_retired_recently`: up to 16 diagnostics of the runs the current daemon generation retired, or `null` when the lifecycle cannot be read (#66).
- `dayz_test_run` results report `steam_startup`, `steam_pid_repair` and `steam_restarted` for their own launch, `null` when unknown (#64).
- `dayz_test_run` and `session_acquire_wait` results carry `caller_tool_registry_stale`; when it is true they also warn `tool_registry_stale_reopen_client` and add `tool_registry_stale_hint`, which says the host must reconnect `dayz-mcp` (#46, #66, #146).
- New runs record `daemon_generation_at_launch`; status, box and `dayz_test_stop` report `daemon_generation_current` and `generation_changed` (#47).
- `dayz_test_run` waits up to 30 s for an unlocked, non-black host desktop before launching a client; `session_locked` / `desktop_all_black` / `desktop_probe_timeout` / `desktop_probe_failed` abort the tandem so it does not burn runs only to return `frame_client_all_black`. Non-Windows `desktop_probe_unsupported` does not block (#88).
- `vehicle_trace` `mode=dump` writes the canonical trace as JSONL in the profile folder (also on `stop`) instead of sending every sample over the wire. Samples carry `engine_rpm`, `rpm_idle`, `engine_ready` and `throttle_set`, and `classify_14de_throttle_sample` tells an engine-ready skip from setter lag; JSON `1`/`0` count as booleans (#26, #36, #42).
- ESC (`key_press(1)` or a physical key) cancels an open `ui_dialog` that offers Cancel (#68).
- A stdio plan B for hosts whose MCP transport fails at startup: `python -m dayz_mcp.stdio_bridge --print-command` prints the registered `--client` argv, and `--probe` checks `tools/list` in three bounded attempts (#89).
- The doctor reports `DAEMON_STATUS_OK` when the daemon checks ran and found nothing, and `NATIVE_BUNDLE_SOURCE_PINS_OK` / `NATIVE_BUNDLE_SOURCE_PIN_DRIFT` for the sealed launcher's source pins; a launch refused for a stale pin names it (#52, #92).
- `tools/write_packaged_modules_lock.py` records the SHA-256 of the 19 sources sealed into the `dayz-test-v1` launcher in `tools/packaged-modules.lock.json`, and `--check` names each drifted source with the rebuild recipe (#61).

### Changed

- A client registered with `--client-platform claude`, which both installers emit, lists every tool with its full description and output schema before any lease, because Claude Code never re-lists. Other clients keep progressive disclosure: before a lease, `tools/list` shows the core tools (the session tools, `bridge_status`, knowledge, pipeline, `dayz_test_*` and `wait_for`) and the lease-free reads, with descriptions cut at a sentence or word boundary and marked as cut. `tools/list_changed` follows every change of the visible catalog: a grant, a release, and a lease found expired or lost. Hidden tools stay callable; the lease gate is the boundary. The `dayz_test_run` description opens with its cycle (`session_release`, then `dayz_test_run`, then `session_acquire_wait`) (#80, #98, #113, #171).
- `pipeline_resolve` refuses an id with no entry (`feedback_not_found`) instead of appending an orphan resolution, and its reply says whether the entry was `already_resolved` (#166).
- The client car verbs refuse a car this client does not drive with `not_seated`, `not_driver` or `not_owner` (#173).
- The bootstrap pins `pip==26.2.1` in the installer and CI and `setuptools==84.0.0` as the build requirement (#172).
- The 12 vehicle scalar fields travel only on the verbs whose dispatch writes them, even at 0, and are dropped from every other result; `pos_delta`, which no command writes any more, is gone. A `vehicle_control` reply carries only `engine_on_server` (#183).
- Eight descriptions say what a reply does not prove: the `vehicle_control` and `engine_set` reply is not telemetry; the server-side body in `query_player_state` and `query_all_players` does not travel with a client-owned car; `action_use`'s `condition_failed` means this call did not dispatch, not that nothing follows; `session_status` says what `claimable` does and does not mean; `object_doors` gives the measured result of a raycast against a door leaf. `world_spawn`'s example is `type="CivilianSedan"`, and `unknown_type` names the type it received and says `type` is a CfgVehicles classname (#183).
- `session_status.box.foreign_ports` lists only DayZ-related listeners (a DayZ image, or a UDP port in 2302-2999), each as `{port, dayz_relevant}`. The complete socket table minus managed runs, which `foreign_ports` held in v1.2, is now `foreign_ports_all`, and `foreign_ports_meta` counts both (#79, #83, #95).
- `bridge_status.tool_registry_remediation` is `null` when the tool registry is fresh and an object (`code: "reopen_mcp_client"`, `scope: "tools"`, `applies_when`) when it is stale or cannot be verified, instead of the string `"reopen_mcp_client"` every time. `daemon_source_remediation` reports daemon modules that are stale or unreadable (reopening the client does not refresh the daemon), `fence.mutation_rejects_meta` marks the fence counters as historical (`blocks_now: false`), and `session_status.box.available_for` tells `new_launch` from `adopt` (`80ed00b`, #29).
- The bridge announces an argument-contract hash (`ach=`). When it is missing or different, `bridge_status` reports `capabilities.state=mismatch` and `ready=false` with `reason=arg_contract_mismatch`, so a PBO older than the tools fails closed instead of matching on command names alone. `MCP_BRIDGE_VERSION` stays `"10"` (#94).
- While an ownerless `RUNNING_IDLE` run is not `abandoned`, only the session that launched it may adopt it, take it over or stop it. Others get `run_protected` (`box_protected` from `session_acquire_wait`) with `use_state`, `use_reason` and, for `idle` / `human`, `retry_after_s`, and `takeover=true` does not evict it. The launcher's rights survive `server_reload` but not a client reopen or a daemon restart (#135).
- World reads fail fast when `bridge_status.ready` is false: nothing is enqueued, and they return `{ok: false, code: "not_ready", reason, next_step: "bridge_status"}` with `error: "game_not_ready:reason=<token>"`; `wait_for` retries that envelope and `binding_not_ready` (#77, #79, #82).
- For a project other than `DayZ_MCP`, `dayz_test_run` appends `@DayZ_MCP` to `extra_mods` when no spelling of the bridge is there and reports `extra_mods_defaulted`; `bridge_mod_missing` says so when the bridge sits in `base_mods`, which does not count (#143, #146).
- `pack-addon.ps1` packs the git-tracked `addon/` of `-Ref` (default `HEAD`) through a stage verified file by file against the commit, so uncommitted edits are not packed. `-Source <folder>` packs a plain folder instead, skipping editor backups and Markdown, and `-StageOnly` prints the staged files and their SHA-256 without packing. `pack-addon.ps1` and `deploy-addon.ps1` reset `PSModulePath` to the machine value (#62).
- Both installers register the client with `--supervised`, which `server_reload` needs, and `--no-supervised` / `-NoSupervised` opts out. `install_mcp.py` reads a supervised registration back, and `--register` refuses with `registration_would_drop_options` to drop an option the current registrations carry unless `--allow-option-removal` is passed (#121).
- `install-mcp.ps1 -Register` is for new installs: it adds `dayz-mcp` only when neither Claude nor Codex has it, never calls `mcp remove` on that path, probes again right before `mcp add` and stops if the add fails. An existing registration, or an existence check (`claude mcp get` / `codex mcp get --json`) that is missing or unreadable, stops the script: re-register with `python tools/install_mcp.py --register`, or pass `-ReplaceExistingRegistration`. The installers' copies of the registry flags now include `--exec-audit-path`, and one test derives them from `server_cli`'s parser (#129).
- `dayz_test_run` refuses a closed Steam (no `steam.exe` running) with `error_code=steam_not_running` and a remediation that names the cause and the next step (start Steam and wait for its login, or retry with `auto_remediate_steam=true`), in validation, before any DayZ process starts. It used to be `steam_session_stale` with the generic `restart_steam_and_wait_for_active_process_match`. A running Steam with an invalid registration, and a host whose registry or process list cannot be read, still return `steam_session_stale`; the daemon-side gate keeps its codes (#90).
- `run_not_owned` names the way out, `session_acquire_wait`, whose grant adopts the single ownerless run (`next_step=session_acquire_wait`), also when a fenced run discarded a queued command (#98).
- The descriptions of `session_acquire_wait`, `session_status`, `session_heartbeat` and `wait_for` state what renews the lease: calls that reach the box with it (bridge verbs, `players_*` / `entity_state` probes, `dayz_test_run`, `dayz_test_stop`) and `session_heartbeat` do, `session_status` does not, and past the TTL an adopted run becomes ownerless `RUNNING_IDLE` (#66).
- `restore_gameplay` lists `render` in `not_verified` and no longer advises calling it again; `capture_screenshot` adds `render_frozen_signal` to `warnings` when a capture of two or more frames shows a single distinct frame (#65).
- The `object_anim` description says that its reply is a same-tick re-read, that a read writes nothing and a written phase holds, and that building doors are read with `object_doors` (a source reads only under its exact name, and an unknown name also reads 0) and car doors with `vehicle_door` (#154, #162, #163).
- The `world_spawn` description explains that an object spawned without `ECE_NOPERSISTENCY_WORLD` can be saved into a later run, where its `object_id` no longer works, and names `flags=8389668` (#146).
- `world_time_set` carries minute overflow into the hour and day, sets `ok:0` when a complete date echo mismatches, and returns `multiplier_applied=null` with `warnings=["multiplier_unconfirmed"]` because the engine exposes no multiplier getter (#35).
- `pipeline_feedback` publishes its title, body and project length limits in `inputSchema` (#32).
- `fixture_not_ready` from `vehicle_prepare_fixture` carries the observed fixture telemetry under `observed=` (#34).
- The `client_policy_untrusted_open_new_session` hint says when the client registered (#46).
- `capture_screenshot` returns `session_locked` on a locked Windows session instead of launching the grab and failing generically (#45).
- Automatic manual-gearbox upshifts wait a 0.3 s settle interval, reset per drive and on a backward tick clock, and `vehicle_get_in_client` seats the client in the vehicle nearest to `pos` (#44, #54).
- The `dayz_test_run` description states how long the call can block; the `session_release` description states that releasing never stops DayZ (#46, #47).

### Removed

- The internal bridge verbs `vehicle_drive` and `drive_probe_client`, which had no public tool; `vehicle_control` drives. An addon that still announces them shows them as `unmapped_announced_commands` (#68).

### Fixed

- An optional argument the caller omits no longer reaches Enforce as 0: an `object_anim` read no longer writes phase 0 (which had looked like car doors not holding a phase), and a partial `world_weather_set` no longer zeroes the other levels; `world_time_set` and `infected_drive` are covered too. The wire carries `<field>_set: true` beside each optional value, and the daemon refuses a value without its flag (#162).
- The daemon works from a Python 3.11 or 3.12 venv: its identity checks, the orphan reclaim and the legacy port reclaim accept the venv redirector's rewritten `argv[0]`, and the request parser fails closed as `json_undecodable` on nesting too deep for the 3.11/3.12 decoder (#112, #116, #126, #130).
- DayZ Tools on another drive: the bundle verifier finds DayZ Tools the way the builder does (`DAYZ_TOOLS_PATH`, then the registry, then the default), and the sealed launcher starts AddonBuilder from the sealed layout instead of a fixed `C:` path (#123, #128). On a fresh clone the launcher registry lock is created, the builder takes the Windows SDK paths from `tools/dependency-lock.json` instead of a fixed `C:` path, a bundle can be published onto another volume, and README's "Before the first test run" lists the host setup a first run needs (#114).
- `dayz_test_run(build=true)` through the native launcher no longer stops at `native_debug_gate_rejected:unapproved_debug_image`: in the AddonBuilder tree only, the debug gate admits a closed list of Valve-signed Steam client DLLs from the pinned Steam directory and Valve's `bin\x64launcher.exe` (#141, #152, #158).
- Fail-closed path checks (the daemon keyfile, host-config provenance, the installer's CLI path) accept an 8.3 short path to the same file instead of refusing it (#138).
- A session keeps its lease across `server_reload`: the handoff carrier follows heartbeats and lease-renewing commands (`lease_id` in `/enqueue` and lifecycle replies), a release or an invalidation clears it, and its I/O runs off the event loop. A reload that inherits an expired lease recovers without disturbing live or queued leases (#92, #119, #131).
- `session_release` of a token this client still held after a silent TTL answers `lease_expired` with `next_step=session_acquire_wait` instead of `lease_invalid`, and a heartbeat with an expired lease says it expired, even while a fence is up, instead of "token was never valid" (#77, #136).
- Remaining times (`expires_in_s`, queued tickets, grace `remaining_s`) never exceed their caps. `wait_for` never starts a probe after its deadline, and its wait for `tool_lock` counts against `timeout_s` (`timed_out` with `last_error=tool_lock_busy`) (#118, #127).
- In client mode, the readiness probe before a world read is capped by the caller's remaining deadline, so a slow probe no longer stretches the call (`da22937`).
- `dayz_test_stop` succeeds when DayZ is already gone instead of reporting `run_stop_failed` with `cleanup_degraded=true`; a run still alive after a failed stop still fails (#86).
- A lease grant adopts an ownerless `RUNNING_IDLE` or `UNRECONCILED` run whose owner is an empty string; it used to leave `adopted_run` null, and `dayz_test_stop` answered `run_not_adoptable` (#87).
- Manifest backups under `lifecycle-recovery-faults/backups/` stay bounded: the newest 200 plus every one a pointer or a fault names, with at most 128 removals per checkpoint (one host held 1.1 GB of them). A replace blocked by another reader retries for up to 1 s, and a backup a crash left incomplete is quarantined instead of stopping the daemon with `invalid_lifecycle_manifest_backup`. The doctor warns `MANIFEST_BACKUP_RETENTION_STALLED` and `MANIFEST_BACKUP_QUARANTINED` (#53, #63).
- When the MCP host is an MSIX app (Claude Desktop, Codex), the daemon is spawned through WMI, outside the app's registry virtualization, and the stdio Steam check reads the real `HKCU`, so a live, logged-in Steam no longer gets launches refused. `DAYZ_MCP_DAEMON_SPAWN_WMI=0` turns the WMI spawn off (#91).
- Starting a run no longer activates DayZ windows on launch, and the capture helper no longer opens a console window (#59). DayZ still takes the foreground for about 2.5 s once started, whatever the window's initial state; that is the game's own activation (measured 2026-09-30; see Known issues).
- Releasing a scripted `lookat` camera with `restore_gameplay` no longer freezes the client render: the view goes back through a FreeDebugCamera handoff, as vanilla's camera tools do, and the reply is posted when the handoff ends. `render_frozen_signal` also fires for a near-still frame pair (#167).
- `vehicle_control` applies brake and handbrake whatever the engine state and starts the engine only when `throttle` is above 0; a release restores the car's brakes-without-driver, as vanilla does (#170).
- `pipeline_inbox` no longer loses an entry, or the whole read, when a record holds U+2028, U+2029, U+0085 or an undecodable byte: records are split on the newline each one ends with and decoded one by one (#169).
- Concurrent inbox writers no longer lose or tear records: every append holds a cross-process lock on `feedback.jsonl.lock` (bounded at 10 s, then `inbox_busy` and nothing written), and a new id is checked unique under it (`inbox_id_collision` after 16 draws). Measured with the old code on Windows, six concurrent writers kept 255 of 300 records of about 1 KB. The id format, the size limits and the record fields do not change (#179).
- A daemon started from an interpreter other than `tools\.venv-mcp` prints one line naming both interpreters and exits 78 instead of a traceback and exit 1 (#184).
- A stop that races the reaper succeeds honestly (`stop_method: already_exited`) instead of `run_stop_failed` with the box free, and a DayZ launched by `start_run` survives a daemon crash between the launch and the manifest: a versioned `launch-intent.json` written before the launch lets the next daemon start record the orphan when exactly one process matches its argv hash, launch window and profile token (#185).
- `player_teleport` skips its occupant precheck when no client peer can answer it, instead of timing out on that probe (#76).
- `notify_players` with no connected player returns `{ok: false, sent: 0, error: "no_players"}` instead of `sent: 1` (#85).
- `object_inspect` echoes a malformed `type` in its `bad_args`, and a call with neither `type` nor `object_id` names both legal forms (#79, #84).
- `camera_set` restores gameplay when applying the camera fails after the controls were suppressed (#97).
- `capture_screenshot` reports a grab that never started as `capture_start_timeout`, apart from `capture_timeout` (#136).
- In DayZDiag, a client take to hands no longer throws a NULL pointer: the addon registers `PluginInventoryDebug`, which vanilla registers only when `IsDebug()` is true (#160).
- Fresh-launch `bridge_status.ready` no longer reports `server_poll_stale` from a dead pre-launch peer's leftover poll ages; the verdict is `binding_not_ready` until this generation's first accredited poll. ### Security

- DayZ, and Steam when dayz-mcp starts it, run with a whitelisted environment instead of the agent's, so the agent session's environment variables (API keys and other secrets) no longer reach those processes or their crash dumps (#144).
- The daemon checks the arguments of every whitelisted bridge verb against an ingress schema: the 16 verbs that accepted any payload (`world_spawn`, `camera_set` and `vehicle_control` among them) now refuse extra, missing or mistyped keys with `bad_args`, and a verb without a schema is refused (#117).
- Strings from identities or persisted state that reach MCP payloads (the registration stamp, daemon generations, stop-envelope state and reason, retired-run diagnostics) are echoed only when they match a closed shape (#46, #47, #66).
- Both bridges accept only an exact loopback REST URL, `http://127.0.0.1:<1-65535>/`, instead of anything that starts with `http://127.0.0.1:` (#173).
- `dayz_test_close` is denied inside playbooks, next to `dayz_test_run` and `dayz_test_stop` (#175).
