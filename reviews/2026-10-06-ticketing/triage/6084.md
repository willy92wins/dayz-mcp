## ROOT CAUSE
Windows MSIX app-container registry virtualization: some process inside the Claude app once wrote `HKCU\Software\Valve\Steam\ActiveProcess`, creating a private hive copy that shadows the real key for every descendant of the app and freezes whenever Steam restarts. The MCP's mitigation is structural: the daemon is created via `Win32_Process.Create` in WmiPrvSE (outside the container and any caller job), so the daemon and the DayZ processes it launches read the real hive; the in-process preflight can additionally read the real hive via WMI.

## PROPOSED FIX
Recommended: **no new mechanism — close as fixed by #91**, with one verification step: confirm the production call site constructs `WindowsSteamPreflightProvider(real_registry=True)` on the in-app stdio path (the class default at `steam_preflight.py:140,145` is `False`; the call site is NOT SHOWN — see NOT VERIFIED). If that call site passes the default and runs inside the app, the minimal change is to pass `real_registry=True` there (one argument). Behaviour before/after: before, a stdio-side Steam check inside the MSIX app can see a stale `pid` and refuse with `steam_session_stale`; after, it reads the live pid via WMI and only refuses when the *real* registry is stale. Error contract unchanged (`steam_session_stale` / remediation reasons as in `steam_preflight.py:712-765`).

Alternative (only if a launch path is found that spawns DayZ from a possibly-virtualized process rather than from the WMI-spawned daemon): route that spawn through `wmi_host.create_process` exactly as `_spawn_outside_app` does (`daemon.py:1757-1779`). Do **not** implement the ticket's option 2 (writing the pid from inside the app) — `steam_preflight.py:741-744` already rejects that as it recreates the shadow.

## TEST
Unit test (regression for the recommended verification): construct `WindowsSteamPreflightProvider(real_registry=True)`, monkeypatch `wmi_host.read_hkcu_dword` to return the live Steam pid while a patched `winreg.OpenKey/QueryValueEx` fixture returns a stale pid (the "frozen copy"), and assert `read_active_process()` returns the WMI pid with `real_registry_unavailable is None`. It fails with the default `real_registry=False` (returns the stale winreg pid) and passes after the call site passes `True`. In-game equivalent: restart Steam, then `dayz_test_run` through the daemon — before #91 this refused with "Steam not running"; after, it launches (this is the #91 acceptance already recorded in `CHANGELOG.md:116`).
