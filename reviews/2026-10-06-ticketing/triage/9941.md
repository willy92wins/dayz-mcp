## ROOT CAUSE
Continuous actions (`CAContinuousTime` / `UATimeSpent`) only progress while the engine sees the action input held down; `action_use` performs a single `PerformActionStart` with no sustained input, so the engine cancels the action and nothing deploys. DayZ 1.29 exposes no script API to assert a `UAInput` (`no_local_setter`), so neither `action_use` nor `input_trigger kind=input` can hold it today.

## PROPOSED FIX
No defect fix applies; two product options:
1. **Recommended (S, documentation/contract):** keep the behavior and make the limitation actionable at call time — e.g. in the `action_use` reply (or its description, `server.py:6697-6741`) add a hint when the resolved action is continuous, telling the caller that `started=1` will not complete a `CAContinuousTime` action without held input and that kit-placement tests need a human or a mod-side auto-complete. Caller-visible contract unchanged except an added advisory field/hint.
2. **Feature (L):** add a hold mechanism, e.g. `action_use hold_s` backed by a new client command plus a client control (like `MCPInputTriggerControl`) that keeps the action input asserted for the duration — but this requires a script path to assert the `UAInput` that the codebase says does not exist in DayZ 1.29, so it likely needs an engine/mod workaround (e.g. the mod under test exposing a non-continuous variant of the action) and a bridge-version bump.
