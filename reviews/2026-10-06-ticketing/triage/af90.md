## ROOT CAUSE
By design: `wait_for(players_*)` is classified as a pure read (H3), so it probes whatever run the daemon currently serves (`query_all_players` against the box's live game) without checking that the caller holds a lease or owns the run. A leaseless session therefore sees the other session's player count.

## PROPOSED FIX
No code change required by the ticket's own terms ("If cross-session reads are allowed by design, no action"). Recommended: none — H3 already codifies and gates this behaviour offline.
