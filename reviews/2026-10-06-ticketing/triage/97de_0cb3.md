## ROOT CAUSE
`_assert_quiescent`'s blocker scan is machine-wide over all `python -m dayz_mcp` processes regardless of which state root or port they serve. For a fresh state root no receipt exists, so `_settled_receipt` returns None and the gate runs before any write: clients of *other* instances (Grok CLI, Hermes gateway, the 1.29 daemon's pollers) — which cannot mutate this instance's `runs.json` — block the one-time backup until the drain/startup deadline expires (RC 75). The existing post-write drift check (`identity_migration.py:1422-1431`, `runs_source_or_backup_drift`) already catches a genuine concurrent writer, so the machine-wide scan is over-broad defense-in-depth.

## PROPOSED FIX
**Recommended — scope the scan to the instance's own state root (minimal, closes the defect):**
- File: `tools/dayz_mcp/identity_migration.py` (the default `scan_fn` around :739-743, name NOT SHOWN, plus its wiring into `ensure_runs_v1_backup`).
- Behavior before: any `dayz_mcp` process machine-wide is a blocker → `dayz_mcp_process_present` → daemon RC 75 on first start.
- Behavior after: a process counts as a blocker only if it plausibly serves *this* state root — same resolved `RuntimePaths.root` (from its environment/command line where readable) or a listener on this instance's port; undeterminable processes stay blockers (fail-closed). The port-listener probe (`_assert_quiescent`'s `listener_fn`) is already instance-scoped and unchanged.
- Caller contract: first start of a second instance succeeds while unrelated instances' clients run; a same-instance process or a listener on the instance's port still fails with `dayz_mcp_process_present` / `listener_present` exactly as before. The drift check at :1422-1431 remains the backstop for a missed same-root writer.

**Alternative (diagnostic only, does not close the block):** keep the machine-wide scan but log blocker details (pid, executable, owner classification as in ticket 2's script) to the daemon's local stderr/audit before raising, so operators know *who* to stop. Could be combined with the recommended fix.

The "supported instance option" (state root + registration name + port) is a feature request — owner decision, out of scope for this minimal fix.
