## ROOT CAUSE
Not a defect: an ownerless run past the 600 s idle cut reads `abandoned` and then every lease grant adopts it (`CHANGELOG.md:114`), while the only automatic releaser (the idle warden) ships disabled by design, so with the warden off an abandoned run blocks `new_launch` indefinitely.

## PROPOSED FIX
1. **Recommended (no code change): enable the warden.** Write `{"enabled": true}` to `%LOCALAPPDATA%\DayZ_MCP\idle-warden.json`. Before: an abandoned `RUNNING_IDLE` run blocks the box until a human intervenes. After: the warden acquires the lease, warns connected players, and closes the run (WM_CLOSE path) ~60 s later; the box frees, and the retirement shows in `runs_retired_recently` with the `idle_timeout`/`orderly` audit outcome. Caller contract unchanged: `session_status` goes from `blocked_on: protected (abandoned)` to an available box.
2. **Optional (needs owner approval): `session_acquire_wait(adopt=false)`.** In `session_coordination.py`'s grant path (symbol NOT SHOWN), skip the ownerless-run adoption when the flag is set and grant a lease that owns no run; `session_status` would then show the lease with `adopted_run: null`. Risk: it breaks H15's stated invariant that a grant adopts, and a lease-only holder staging files under an abandoned run invites a third session to adopt the same run concurrently.

Request 3 needs no work: `launched_by` is already in the box rows (`process_lifecycle.py:666`) and `_box_holder_session` already surfaces it as `occupied_by_session` (`box_occupancy.py:630-632`).
