§0. EL PRODUCTO
===============================================================================

  P6. **Sin dueño no se despacha NADA, y el cerco va antes de publicar.** Con el run en
      `RUNNING_IDLE` se rechaza TODO comando dirigido a él por su binding —lectura, mutación o
      `internal=True`— con `run_not_owned` (409), y nada acredita actividad. El cerco es un
      estado lógico de `ServerState` (no la retirada física del binding), activado bajo el
      MISMO lock que usan enqueue y poll, con la cola vaciada AHÍ, ANTES de que
      `manifest.release_owner` persista `RUNNING_IDLE`; el poll de un binding cercado devuelve
      `commands: []` (el bridge sigue vivo); si la persistencia falla, el cerco se revierte;
      `adopt_run` lo levanta. Vale para las DOS entradas del release (`release_owner` directo
      y `begin_release_owner` reconocido) y para `admin_reconcile` con supervivientes. El
      cleanup interno del release (`vehicle_release` interno) se entrega o se descarta ANTES
      de publicar `RUNNING_IDLE`; después, es un comando más y se rechaza. `STARTING` sigue
      despachando. La retirada física queda para stop/reap/repair/reconcile-sin-supervivientes.
  P7'. **La tumba es la frontera del rollback.** En `_settle_failed_launch`, ANTES del
      `manifest.replace(target)` del rollback se marca el run como «compensando» bajo
      `_activity_lock`; mientras dure, el único punto de escritura de sellos
      (`_seal_activity_locked`) DESCARTA cualquier crédito o basal para ese run; tras
      persistir el rollback se ejecuta la compensación (olvida sellos con época en
      `[inicio del intento, ahora]`), se eleva la tumba a ese instante y se levanta el cerco.
      Un crédito posterior al levantamiento aterriza. Si el `replace` del rollback falla, el
      cerco se levanta igualmente (nunca queda un run mudo para siempre).
  P8. Sin cambios: el sello del caché de sondas se muestrea antes que el dato.

Sigue en pie todo lo anterior (P1-P5, P7 tumbas por época para la observación sin binding,
